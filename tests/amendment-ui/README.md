# Browser regression checks: contract amendments

Floating-action checks include a chat-launcher fixture matching the real launcher's `bottom-6 right-6`, 48px mobile / 56px desktop footprint outside the page container. Both export and amendment-save bars align along the same bottom edge as chat, inset to its left with at least 16px clearance, including after automatic scrolling. Narrow screens wrap actions inside that reserved width rather than covering chat.

Uses the actual contract sections, inline editor, modal, panel and client service in an isolated Playwright browser with intercepted API fixtures. No requests reach the live backend, payment APIs or SmartCA; no login is reused. Nineteen flows check read-only defaults, direct rent editing, review/consent and signing order, text-only tenant requests, private drafts and resume, mobile overflow, eligible billing-boundary calendar, formatted VND/suggestions, editable document identity/banks/deposit/cycle, typed numbers/dates, unit-number fallback without phantom changes, fixed property feature rows (values editable, no add/remove), aligned prices on desktop/mobile, freely added/removed equipment/amenities/fees/policies without the Listing API and special-term replacement. The system-billing flows verify that only late-fee mode/rate are submitted, the mode dropdown has exactly three canonical options, daily-to-once recalculates the displayed ceiling, NONE clears/disables the amount, deadline/grace/cap have no inputs, and the protected system paragraph stays outside editable notes. Other Listing-derived fields remain free text. Every amendment, including non-financial changes, has a future billing-boundary date; there is no immediate radio option. Scheduled replacements prefill the signed proposal, lock its original effective date, permit reverting to base terms and require renewed consent while preserving the old signed schedule until verified replacement signatures. Pure helpers check currency normalization, posting-policy payloads and month-end/date conversion. Java tests separately cover business validation, prepaid rent coverage, deposit delta receipt/idempotency, canonical calculations, Word-template population/comparison appendix and verified signatures before applying a new snapshot. The billing regression uses the real amendment terms builder and effective-date resolver to verify mode transitions on future cost periods without repricing issued invoices. The document dossier flow runs for landlord and tenant: collapsed Word/PDF history including STALE files, signed/pending/future/rejected records, audit-order numbering, historical comparison labels, verified signature timeline, per-group retry, real PDF viewer opening, refreshed authorized view/download URLs and mobile layout. The export flow uses the real header on desktop/mobile: its bottom bar remains fixed after scrolling, clicking export scrolls to page top, pending export disables repeat clicks, and tenant/non-draft views cannot export. Browser tests mock the API, not the business-rule calculations.

Field-state UX: contractual values that allow amendment are blue; protected records and derived values use foreground text; actual draft changes are green and carry a text label. Tests compare computed colors, restoring source values, leading-zero bank numbers, number/money/date fields, policies, table additions/removals, legacy aliases, saved draft resume, and signed scheduled replacement baselines. Green indicates an edit, not effectiveness; red remains available for actual validation errors. This is presentation only: no automatic signing or changes to backend permissions. Reverting a value restores blue; untouched rows do not turn green because an earlier row was removed.

The three-category bank/ledger flow checks both landlord and tenant read-only views, all six bank fields, zero-prefixed bank numbers in amendment inputs/payload, and preservation of the initial payment snapshot. The Node schema audit reads CONTRACT_PROMPT.md and ContractFieldCatalog.java directly (64 catalog markers, 56/57/57 prompt-body markers, 27/28/28 mandatory markers); all markers must route to a mounted section or an explicitly protected/derived record. Backend tests populate/render all 64 markers and verify bank amendment mapping for HOUSE/APARTMENT/ROOM.

Install/provide Playwright outside this test if it is not already available. Run `node tests/amendment-ui/run.cjs [absolute-path-to-playwright-module] [optional-browser-executable]`. TypeScript, Webpack, PostCSS and Tailwind come from this app's existing dependencies; CSS is compiled from the current sources for visual QA. Generated bundles/styles/screenshots stay in the ignored `output` folder.
